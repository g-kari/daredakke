# 画面と入力破棄のブラウザー回帰テスト

npm ci 後、npx playwright install chromium と npm run test:browser で実行します。

通常のvite buildで生成した実画面をlocalhostのpreviewで開き、Playwright側で /api/session と /api/records を架空データに置き換えます。本番の認証・API・D1は使わず、localhost以外への通信を遮断します。実装にデモ用の認証回避やテスト入口を追加しません。

デスクトップと390pxのモバイル幅で、Escape / キャンセル / 閉じる / 背景クリック、入力の保持と破棄、フォーカス復帰・トラップ、通常保存、JSONの保持、繰り返しのWebMCP追加要求、本人変更時の入力消去を確認します。WebMCP登録先だけをテスト用に差し替えるため、対応ブラウザーでのWebMCP通信互換性を証明するテストではありません。

CIは読み取り専用のpermissionsで同じテストを実行し、最終ソースSHA、JSON結果、失敗時のtraceとスクリーンショットを1日間だけ保存します。証拠には架空データだけを使います。本番Cloudflare Accessとの接続、実機スマートフォン・支援技術の操作は別途確認が必要です。

人・アカウント・JSONの未保存入力では、破棄確認が表示されて「編集を続ける」にフォーカスした直後の2回目のEscapeも確認します。各入力で5回繰り返し、入力保持・元の入力欄へのフォーカス復帰・保存リクエスト0件と、最後の明示的な破棄を検証します。固定sleep・キーの再送・回数や失敗を緩める変更は使いません。6ケースを既存88ケースへ追加し、実行結果は対象SHAのCIを参照してください。

プロフィール中心のB2-4画面は、検索・サービス絞り込み、一覧と詳細の選択状態、モバイルの詳細を閉じた際のフォーカス復帰、文脈に合った追加・編集、保存ツール、長文の横はみ出しも確認します。最初の一覧とプロフィールのスクリーンショットをtest-results/uiへ保存します。画像は架空の4人と手入力アカウントだけです。34ケースの合格状況は対象コミットのCI結果を参照してください。

複数キーワード検索はkeyword-search.spec.mjsの11シナリオを同じデスクトップ・モバイル設定で確認します。名前・別名・タグ・メモ・アカウントの手がかり、順序の入れ替え、大文字小文字、連続空白・全角空白、空白だけの入力、正規表現として扱わない記号、サービス絞り込み、未整理と重複候補の各行単位のAND条件を対象にします。検索ヒントの説明づけ、選択とフォーカス、空の保存先、デモとマイレコードの分離も確認します。

この検索用fixtureはhttp://127.0.0.1:4317のGETだけを許可し、外部通信・予期しないAPI・保存リクエストを遮断して失敗にします。WebMCPは既存と同じmodelContext登録fixtureで、実画面と結果の一致、100文字の制限、繰り返し呼び出しで保存しないこと、人・アカウント・JSONの未保存入力の保持、ログイン確認中の拒否と本人変更時の消去を確認します。ネイティブWebMCPの互換性や本番Accessの接続を証明するものではありません。最終候補の一覧・プロフィール・重複候補の架空スクリーンショットはtest-results/keyword-searchへ保存します。実行可否と合格状況は最終ソースSHAの通常CIで確認してください。

読み取り期限と復旧はread-recovery.spec.mjsで確認します。実ビルドのUIをデスクトップ・390px幅のChromiumで開き、初回のrecords/sessionと再確認sessionのfetch・JSON本文をそれぞれ停止します。Playwrightの時計で14,999msでは未確定、15,000msで安全な復旧画面になることを検証し、固定sleep・再試行・期限の短縮は使いません。制御するPromiseはAbortSignalを意図的に無視し、遅れて成功しても自動復旧や古い本人情報の反映が起きないことを確認します。

本人の明示的な再確認だけで人・アカウント・JSONの入力が戻ること、別人・401・403・503・不正な認証応答で古い記録と入力が消えること、重なったfocus/visibility確認では新しい操作に15秒が与えられることを対象にします。確認中と期限切れにはWebMCP・保存・既存の書き出し操作を拒否し、フォーカス復帰や時間経過から自動で再試行しないこと、POST・ダウンロード・クリップボード・Storage書き込みが0件であることも検証します。全APIはページ初期化時の架空fetch応答に置換し、APIが実ネットワークへ漏れた場合も失敗させます。

JSON置き換えの最終確認や人の入力破棄確認が開いている時の期限切れも確認します。同じ本人で復旧すると入力とJSONレビューを保持し、古い確認ダイアログは自動で開き直さず、保存要求も発生しません。本人の操作で改めて確認を開くまで待つことを検証します。

42ケースの収集対象を追加しています。実行時には復旧画面と本人再確認後の保持入力をtest-results/read-recoveryへ画像として保存し、Playwrightの結果にも添付します。ブラウザーの実行と画像生成の成否は実際のラン結果で確認してください。テストの収集・構文確認だけでは合格や画像生成を意味しません。本番Accessとの接続やネイティブWebMCP互換性は検証しません。
