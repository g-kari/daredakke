# だれだっけ

人を軸に、名前・別名・タグ・メモとDiscord / X / VRChatのアカウントを整理する本人専用ツールです。

Cloudflare Workers + D1版は https://daredakke.0g0.xyz に本人限定で配備されています。リポジトリ内のD1 IDと認証値は設定例で、本番の実値はCloudflare側で管理します。未リリースの変更の配備状況は更新履歴と対象PRで確認してください。外部サービス連携と元の私用試作からの実データ移行は行っていません。

## 構成

- React / TypeScript / Viteの画面
- Cloudflare WorkerのJSON APIと静的ファイル配信
- D1の記録保存と更新revisionによる競合防止
- Cloudflare Accessの署名付きJWTを検証する本人認証
- デモとマイレコードを分離
- 人・アカウントの追加と編集、検索、未整理アカウントの手動紐づけ
- 名前・別名・タグ・メモと関連アカウントを、空白で区切った複数のキーワードで絞り込み
- 同一サービスの正規化URLが一致する登録の重複候補、手動統合と復元
- version 1 JSONの書き出しと検証付き読み込み
- JSON読み込み前に現在と読み込み後の件数、同じIDでの追加・更新・取り除く・変更なし、未整理と重複候補を確認
- 未保存の人・アカウント・JSON入力を閉じる際の破棄確認
- 読み込み・ログイン確認の15秒制限と、本人を再確認して未保存入力へ戻る操作

サービス接続はすべて未接続です。URL・IDの手入力のみです。顔や名前から同一人物を推測しません。サンプルは架空で、デモのプロフィールURLを外部へ開くことはできません。

## まずローカルで確認

Node.js 22.13以上が必要です。クラウドへの認証やAPIトークンは不要です。

pnpm 11.25.0を使用します。未導入なら `npm install --global pnpm@11.25.0` で固定版を準備してください。依存関係は `pnpm-lock.yaml` を正として、CIと同じfrozen installを使います。Node.jsの既存要件は変更しません。

1. pnpm install --frozen-lockfile
2. pnpm run types
3. pnpm run check
4. pnpm run db:local
5. pnpm run dry-run

checkは型検証・暗号検証・実際のローカルD1を使うAPIテスト・画面のビルドを実行します。未保存入力の実画面テストはpnpm exec playwright install chromiumの後にpnpm run test:browserで別途実行できます。架空のAPI応答だけを使い、Cloudflare本番や外部サービスには接続しません。詳細は[ブラウザー回帰テスト](tests/browser/README.md)を参照してください。db:localはローカルD1のみにマイグレーションを適用します。dry-runは配備せずにWorkerを束ねます。

本番認証設定が空のままでは、画面もAPIも503で拒否します。pnpm run devで公開可能な認証バイパスは用意していません。pnpm run deployは準備版では意図的に停止します。

JSONのファイル保存を開始する際に例外が起きた場合は、書き出し画面とJSONを残して再試行・コピーを案内します。開始の通知は端末への保存完了を保証しません。ブラウザーによる無通知のブロックや保存のキャンセルは検出できないため、保存先を確認してください。

## 本人専用認証

環境変数はdocs/environment.schema.jsonに定義しています。

- APP_ORIGIN: 承認された本人専用ホストのhttpsオリジン
- ACCESS_TEAM_DOMAIN: 承認されたCloudflare Accessチームのhttpsドメイン
- ACCESS_AUDIENCE: このアプリ用AccessのApplication Audience（AUD）
- OWNER_EMAIL: 本人として許可する1つのログインメールアドレス

すべて非秘密の設定値です。秘密鍵、Accessサービス・トークン、Cloudflare APIトークンをソースや画面へ入れません。

WorkerはCf-Access-Jwt-AssertionのRS256署名・issuer・audience・期限・not-before・app種別・本人メール・空でないsubjectを検証します。JWT内のissuerから公開鍵URLを決めません。公開鍵の取得先は設定済みチームに固定します。昔のSites用oai-authenticated-user-*ヘッダー、単なるメールヘッダー、未検証のcookieは信用しません。サービス・トークンも受け入れません。

公開鍵のresolverはWorkerの同じisolate内で再利用します。検証済みissuerごとの最大4件のLRUキャッシュで、取得のtimeoutは5秒、未知の鍵による再取得のcooldownは30秒、公開鍵の有効期間は10分です。期限内の鍵は公開鍵エンドポイントの一時停止中も使えますが、期限切れや不明な鍵は認証を拒否します。JWT、メール、本人判定はキャッシュしません。

静的ファイルを含む全リクエストが認証Workerを先に通ります。workers.devとpreview URLは無効です。実際のAccessアプリ、許可ポリシー、ホスト保護の作成・変更には事前承認が必要です。

保存先は署名検証後のissuerとsubから作るユーザー別namespaceです。デモ、マイレコード、復元履歴もその中で分離します。保存時は読み込み時のnamespaceと現在のログインの一致を確認し、切り替わっていたら古い入力を保存せず画面から消します。URLやJSONのowner指定は保存先を変更できません。

これは将来の複数ユーザーに備えた分離の土台です。今のWorkerの許可メールはOWNER_EMAIL 1件のままで、他ユーザーのログイン、一般公開、共有、登録画面は有効にしていません。詳しくは [認証とユーザー分離](docs/AUTHENTICATION.md) を参照してください。

## 本番へ進める前

画面の配布には2通りあります。通常のwrangler.jsoncはCloudflare Static Assets用です。API経由でupload-sessionの認証を扱えない接続では、pnpm run bundle:workerで画面を同じWorkerのbundleに含められます。どちらも元の認証入口を先に通り、別の公開Workerや資格情報は不要です。bundle方式は合計1MB・100個までのUTF-8ファイルに限定します。通常のStatic Assetsとは異なり、静的応答にもWorkerの利用量がかかります。

docs/DEPLOYMENT.mdのチェックリストに従ってください。ソースはユーザーが用意した [g-kari/daredakke](https://github.com/g-kari/daredakke) で管理します。CIは型検証・テスト・ローカルD1・配備しないdry-runだけを実行し、Cloudflareへ配備しません。

D1のdatabase_idはローカル用の置換必須値です。承認後に対象アカウント、データベース、本人専用ドメイン、Accessアプリを確認し、実際の値へ置き換えます。設定後はpnpm run typesをやり直します。

## 保存と互換性

検索は大小文字を区別せず、空白で区切ったキーワードをすべて含む記録を探します。例えば「あおい ワールド制作」で名前とタグを合わせて検索できます。前後・連続・全角の空白を区切りとして扱い、空白だけなら選択したサービス内の全件に戻ります。記号は文字として扱い、曖昧な同一人物判定・自動紐づけや検索のための記録保存は行いません。既存WebMCPの人検索も同じ規則です。人の検索では、その人の名前・別名・タグ・メモと紐づいたアカウントの手がかりを合わせて探せます。未整理・重複候補の検索は、各アカウントの表示名・URL・サービスと、紐づけ済みなら人の名前を対象にします。未整理・重複候補では、キーワードを別の人や別のアカウントから寄せ集めて一致させません。

重複候補の「記録を確認」で未整理アカウントを開くときは、対象を隠す検索だけを解除します。対象に一致している検索とサービスの絞り込みは保持し、記録を保存・変更しません。

新しい人の保存に成功すると「人」へ移り、追加した人のプロフィールを表示します。その人を隠すサービス条件は「すべて」に戻し、隠す検索だけを解除して通知します。一致する検索は入力した表記のまま保持します。モバイルの詳細を閉じた後も、その人が一覧に残り、もう一度開いてアカウントを追加できます。追加専用のブラウザー履歴は作らず、通常の検索・タブ操作は従来どおりです。保存中・通常の保存失敗・キャンセルでは表示条件を変えず、既存の人を編集した後の動作は変更しません。

新しいアカウントの保存に成功すると、未整理なら「未整理」の一覧へ、紐づけ済みなら選んだ人のプロフィールへ移ります。その登録を隠す検索・サービス条件だけを解除して通知し、一致する条件は入力した表記のまま残します。人のプロフィール内には、その人の全サービスのアカウントを表示します。保存中・通常の保存失敗・キャンセルでは表示条件を変えません。既存アカウントの編集や紐づけ操作は従来どおりです。反映状況と実画面の合格状況は対象PRと最終SHAの検証記録を参照してください。 長い一覧でも、追加したアカウント行へ一度だけ移動してキーボードフォーカスを置きます。本人確認中は待ち、本人や表示先が変われば古い移動を取り消します。

- 記録はD1に保存します。localStorageを記録の保存先にしません。
- 保存文書は操作履歴を含めUTF-8で850KBまで。JSON読み込みは900KBまで。
- 人200件、アカウント1,000件、別名とタグは各20個まで。
- 復元は履歴にある直近10操作です。長期の保管はJSONバックアップが必要です。
- 既存の人・アカウントを編集し、保存時の正規化後も同じ内容なら編集画面内に「変更はありません」と表示し、入力を残します。続けて編集するか、通常のキャンセルで閉じられます。案内は次の入力で消えます。サーバー保存や履歴追加は行わず、過去の復元枠を消費しません。別名・タグや記録の順序、紐づけ、値の意味ある差は変更として保存します。JSON読み込み・新規追加・紐づけ操作・元に戻すは従来どおりです。
- 新しい書き出しはformat: daredakke / version: 1です。旧format: friend-record / version: 1も読み込めます。
- 読み込みはユーザーが選択した保存先だけを置き換え、直前の状態を復元用に保持します。
- 読み込みの確認はまだ保存しません。ファイル名または貼り付け操作を入力元として示し、既存のIDだけで件数を比較します。名前やURLから人を推測せず、別名・タグの並び替えも更新に数えます。形式の検証は作成者や内容の正しさを保証するものではありません。
- JSONを編集すると確認をやり直します。0人・0アカウントへの置き換えは、記録を空にする確認を選んでから最終確認へ進みます。取り除かれる記録がある場合は、先にJSONを書き出して保管してください。
- 元Sitesの本番データを取得・移行する処理はありません。実データ移行は別途許可とバックアップ確認後に行います。

読み込みとログイン確認のGETは、応答本文の読み込みも含め1回15秒で中断します。時間切れでは記録や入力を非表示にし、自動では再試行しません。「ログインを再確認する」で同じ本人を確認できた場合だけ、メモリー内に残した人・アカウント・JSONの入力へ戻ります。ページを閉じると未保存入力は失われます。本人の変更・認証拒否・時間切れ以外の確認失敗では従来どおり入力を消します。保存POSTには時間切れや自動再送を追加していません。

保存POSTの応答がHTML・空・壊れたJSONだった場合や、成功応答のrevisionを確認できない場合は、ログアウトと決めつけず、人・アカウント・JSONの入力と読み込み済み記録をこのページのメモリー内だけに保持します。記録と入力は非表示にして、「ログインを再確認する」で同じ本人を確認できた場合だけ編集へ戻ります。保存された可能性があるため、成功とは表示せず、POSTの自動再送・記録の再読み込み・revisionの更新はしません。本人確認後に入力を控え、別のタブで保存済みの内容を確認してから、必要な場合だけ保存してください。すでに保存されていれば、古いrevisionでの明示的な再試行は既存の競合チェックで拒否されます。ページを閉じると未保存入力は失われます。401・403・明示的な本人変更、および本人再確認の拒否・通常の失敗では古い入力を消します。通常のJSONエラーとネットワーク例外の扱い、API・認証方式・D1は変更しません。

## 検証の限界

本番Cloudflare Accessとの接続、公開されたCloudflareでのエンドツーエンド保存、実機スマートフォンと支援技術の操作は未検証です。未保存入力のキーボード操作と390pxのモバイル幅は、架空APIを使うChromium回帰テストの対象です。合格状況は対象コミットのCI結果を確認してください。WebMCPは対応ブラウザーを検出したときだけ検索と人追加画面を開くツールを登録しますが、対応ブラウザーでの実行検証は未実施です。

### 人の統合時の上限確認

統合の最終確認を開く前に、引き継ぐ別名・タグ・メモが既存の上限内に収まるか確認します。統合元の名前は別名に追加するため80文字までです（統合先と同じ名前は追加しません）。重複を除いた別名・タグは各20個まで、連結時の空行を含むメモは6,000文字までです。超える場合は整理が必要な項目を統合欄に表示し、保存や切り捨ては行いません。案内は通知が消えた後も残り、統合ボタンの説明として支援技術へ伝えます。別の統合元・表示する人を選ぶか統合に成功すると解除します。名前自体の100文字上限や保存形式は変更していません。

### 人詳細のアニメーション（未配備）

モバイルの人詳細Sheetは @animate-ui/react 2.0.0 のRadix Dialog primitiveとMotion 14.4.0で一覧からの移動を示します。既存のキーボード操作・フォーカス復帰・保存方式は変えません。OSの動きを減らす設定では横方向の移動を抑えます。desktopの詳細は従来のままで、追加のアニメーション用コードは読み込みません。モバイルで追加コードを読み込み中、または取得に失敗した場合も従来のRadixで詳細を開けます。開いている途中で実装を入れ替えず、閉じた後に次回から有効にします。[Motionのライセンス通知](docs/MOTION-NOTICES.md)も同梱します。Animate UIは単純なMITではなく[MIT + Commons Clause](docs/ANIMATE-UI-LICENSE.md)です。アプリへの利用は可能ですが、コンポーネント自体の販売・元の形での再配布は制限されています。

### JSONコピーの完了表示

書き出し画面を閉じた後や、新しいコピー操作の開始後に届いた古い成功・失敗は表示へ反映しません。コピーを再試行すると以前の「コピー済み」を解除し、失敗時は画面内に選択コピーへの案内を残し、JSONの領域だけをスクロールできます。開始済みのOS側コピーそのものを取り消す保証ではありません。
